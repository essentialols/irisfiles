Why some OTF files cannot become TTF here

.otf describes an OpenType font container, not one specific outline type. Many OTF files use cubic CFF outlines, while a true TTF needs quadratic TrueType glyf/loca outlines. The browser-side serializer IrisFiles uses can write CFF OpenType output, but it cannot generate those TrueType outline tables. IrisFiles therefore refuses CFF-based OTFs instead of changing only the extension or handing you a structurally incorrect TTF.

If the OTF already contains TrueType outlines, IrisFiles can save those existing sfnt bytes as TTF without rebuilding them. If your goal is a web font rather than a TrueType outline conversion, OTF to WOFF keeps the original outline format.

Frequently Asked Questions

IrisFiles checks the font's underlying outline flavor in your browser. An OTF that already contains TrueType outlines can be saved as TTF without rebuilding its tables. A CFF-based OTF cannot be safely rebuilt as a real TrueType font by the current browser library, so IrisFiles stops without creating a file.

For a compatible TrueType-outline OTF, IrisFiles preserves the underlying sfnt bytes. CFF-based OTFs are not converted, because rebuilding cubic CFF outlines and advanced font tables as TrueType would not be lossless or reliably supported here.
